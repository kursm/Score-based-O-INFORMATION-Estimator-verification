# Эксперимент SΩI, Line-MINE и Line-NWJ

Откройте **start_gui.cmd** двойным щелчком.

В окне только пять настроек:

| Настройка | Что меняется |
|---|---|
| dim U | Число Gaussian-признаков в каждом блоке |
| dim V | Число независимых V-признаков в каждом блоке; 0 — без V |
| Размер выборки | Число уникальных обучающих объектов, минимум 256 |
| k | Число случайных высот кусочно-линейной плотности V |
| Максимум шагов | Общий предел optimizer updates каждого метода |

Нажмите **«Запустить»**. Программа сама обучит три метода на **10 различных значениях
истинной O-информации**. В окне видны текущая точка, метод, шаги, прогресс и ожидаемое время.
**«Открыть PDF»** показывает линейный вид кривых, полный диапазон и сравнение ошибок с GT
в одном файле. Истинная Ω по X, оценки методов по Y; пунктир — точный ответ.
Доверительные интервалы отключены.

Готовый PDF сохраняется в папка_результатов/report/figures.pdf.
«Обновить PDF» пересобирает его по сохранённым результатам без обучения.
«Остановить» сохраняет checkpoint на безопасной границе шага.
Для продолжения оставьте тот же каталог и включите «Продолжить».
Старые результаты с другими настройками остаются в своих папках.

## Исправить уже построенный отчёт

Откройте **start_report_repair.cmd** двойным щелчком, выберите папку эксперимента
(например, res4) или её подпапку report и нажмите **«Исправить отчёт»**.
Это отдельное окно; Python-скрипт оболочки — repair_report_gui.py.

Из терминала тот же инструмент работает без окна:

    .\.venv\Scripts\python.exe repair_report.py res4

Скрипт читает runs/*/result.json; при необходимости восстанавливает оценки из
results.jsonl или results.csv. Повреждённый PDF ему не нужен. Если остался только
PDF/PNG без чисел, он сообщает об этом и не выдумывает данные.
Обучение не запускается, исходные оценки и checkpoint не меняются.
Прежний report сохраняется целиком в report_backups, затем заменяется figures.pdf.
Если PDF заблокирован просмотрщиком Windows, закройте его и повторите.

Для одной серии в новом PDF три страницы:

1. Линейный вид. Огромные выбросы отмечены треугольниками у границ, а близкие кривые
   различаются штрихами и маркерами. При отсутствии выбросов видны все точки.
2. Полный диапазон с symlog по Y: все конечные значения кривых, включая отрицательные и ноль.
3. Ошибки относительно GT и таблица MAE, RMSE, максимальной ошибки и числа побед в точках.

Вопрос «SΩI лучше?» оценивается по ошибкам, а не по высоте линии.
Меньшие MAE/RMSE лучше; сравнение использует общие точки и seeds, сбои не засчитываются
как победы. При повторах внешние seeds имеют равные веса. Ничьи показаны явно.
Вердикт относится к данной серии и не доказывает универсальную оптимальность метода.
Критерий плато validation loss также не гарантирует точности Ω.
Числа сохранены в report/comparison_metrics.json и report/comparison_points.csv.

## Файл настроек

Редактировать достаточно [configs/experiment.json](configs/experiment.json):

    {
      "u_dim": 1,
      "v_dim": 1,
      "n_samples": 10000,
      "k": 16,
      "max_steps": 20000
    }

Кнопка сохранения настроек записывает именно эти пять значений.
Остальные параметры — внутренние исходные настройки методов, без редактора в основном окне.

## Что выбирается автоматически

Используется авторский **mixed Gaussian benchmark, N=10**:
redundancy-подсистемы из 3 и 4 блоков и synergy-подсистема из 3 блоков.
Сила redundancy проходит 10 значений ρ из авторского job script:
0.1, 0.2, 0.25, 0.3, 0.35, 0.375, 0.4, 0.45, 0.5, 0.6.
У synergy фиксировано ρ=0.7. Для каждой точки Ω вычисляется аналитически из ковариации U.
На графике получаются 10 настоящих значений Ω, а не десять повторов одного ответа.

Высоты V независимы и равномерны на [0,1], абсциссы — 1,…,k; крайние высоты в 0 и k+1 нулевые.
Непрерывная кусочно-линейная плотность точно нормируется и сэмплируется.
Для каждой V-координаты плотность фиксирована на всём train/val/test и одинакова между методами.
Масштаб V стандартизуется её точными моментами. При смене ρ V остаётся той же.
Полная размерность равна N·(dim U+dim V); V не создаёт новых блоков O-информации.

Архитектуры, Adam и его параметры взяты из официального кода:
SΩI — lr=0.01, batch=256, EMA=0.999; Line-MINE/NWJ — lr=0.001, batch=64.
Размер сети автоматически выбирается исходным правилом по размерности.
Используются только эти три оценивателя. Установка Python/CUDA остаётся прежней.

## Остановка обучения

Каждый метод останавливается при **плато validation loss или по максимуму шагов**.
Проверка loss выполняется каждые 500 updates на фиксированных 1024 validation-объектах
с отдельным фиксированным RNG. Используется сглаживание 0.5; после 5000 updates
отсутствие относительного улучшения 0.001 в течение 8 проверок считается плато.
Если задан меньший предел, обучение заканчивается по пределу.

Это заранее заданный практический критерий остановки, добавленный в проекте;
авторы статьи использовали фиксированные бюджеты.
Истинная Ω и test не участвуют в остановке. Лучший по test checkpoint не выбирается.
В result.json записывается причина converged или step_limit; состояние проверки
сходимости сохраняется в checkpoint и корректно восстанавливается при resume.
Лимит шагов одинаков для трёх методов, остальные настройки оптимизаторов остаются исходными.

## Запуск из терминала

Из корня проекта:

    .\.venv\Scripts\python.exe -m soi_nuisance gui
    .\.venv\Scripts\python.exe -m soi_nuisance run --preset experiment --dry-run
    .\.venv\Scripts\python.exe -m soi_nuisance run --preset experiment
    .\.venv\Scripts\python.exe -m soi_nuisance run --preset experiment --resume

Короткая проверка всей серии (150 updates, без заявления о сходимости):

    .\.venv\Scripts\python.exe -m soi_nuisance run --preset experiment --set n_samples=1024 --set max_steps=150 --set output_dir=results/ten_point_check_repeat

Проверить код:

    .\.venv\Scripts\python.exe -m pytest -q
